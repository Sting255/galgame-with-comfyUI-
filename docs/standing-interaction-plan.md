# 立绘小窗全身空手触摸方案

更新：2026-10-02。按最新需求替换原先的校准区域、羽毛和玩偶方案。

## 使用流程

1. 用户通过原有入口打开立绘展示小窗，默认即可空手触摸，无需启用、校准或选择道具。
2. 点击或轻划同一部位后松手，播放短暂动作和一条缓存对白。台词显示约 3.2 秒，淡入淡出 0.3 秒。
3. 采用统一的标准正面站姿区域，按图片已有的非透明人物边界缩放，透明留白不参与比例计算。
4. 左右手、左右腿共用各自部位的台词池。同一部位避免连续两次重复；650ms 内的重复输入忽略。
5. 没有专属台词的旧角色先显示普通触碰描述；不会因第一次触摸自动请求模型。

## 固定区域

全身 11 类，每类三句，共 30 句。范围是宽松的固定比例，不进行姿态识别。

| 部位 | 人物有效高度范围 | 横向范围 |
| --- | --- | --- |
| 头顶 | 0–7.5% | 全宽 |
| 脸 | 7.5–16.5% | 全宽 |
| 颈部 | 16.5–23% | 中间 32% |
| 肩膀 | 16.5–23% | 两侧各 34% |
| 手 | 23–58% | 两侧各 24%，覆盖手臂及手掌的宽松范围 |
| 胸口 | 23–35% | 中间 52% |
| 肚子 | 35–47% | 中间 52% |
| 臀部与下体 | 47–58% | 中间 52% |
| 大腿 | 58–77% | 全宽 |
| 小腿 | 77–93% | 全宽 |
| 脚 | 93–100% | 全宽 |

正面站姿无法呈现真实背面臀部，故用胯部所在高度作为臀部与下体区域的近似判定。坐姿、夸张抬手、尾巴或大型武器明显扩大边界时不承诺解剖学精确命中；这是固定区域方案的实际边界，不再转嫁给用户校准。

命中层与立绘使用同一 SVG 变换矩阵；窗口缩放、呼吸与摇摆不应导致坐标漂移。区域保持透明，点击不显示判定范围；支持键盘焦点和 Enter / 空格。

## 台词生成与费用

整套立绘请求通过校验并入队后，同时启动一个独立异步台词任务。复用后端现有 LLM 接口，无需新建操作系统进程或单独部署 worker。

- 整套新生成：一次台词任务，单份完整 JSON，包含 10 个部位 × 3 句。
- 单张补图、图片编辑、复用提示词的单张重试、同批暂停后继续：不额外生成台词。
- 同角色已有台词生成任务时复用进行中的任务，避免重复调用。
- 台词请求与图片队列互不等待，台词失败不影响立绘出图。实际网络并发仍遵守系统已有 LLM 限流配置。
- 请求总超时 90 秒，关闭常规请求重试与 SDK 重试；不在触摸时重试或生成。
- 再次生成整套立绘时允许刷新台词。旧台词在新任务进行中和失败后继续可用。

提示词使用完整角色资料，要求角色口吻、称呼习惯、自然的即时反应，每句 4–32 字。包含所有字段与每条内容约束的完整 JSON 示例；只接受完整的 30 句，不接受缺项、重复、越界长度或额外顶层字段。反馈保持日常、非露骨，角色可以表达惊讶、怕痒或边界。

## 数据与状态

新增 `character_standing_touch_lines`：`character_id`、`request_id`、`status`、`lines_json`、`error`、`updated_at`。

- 状态：empty（无记录）、generating、ready、failed。
- 写入按请求标识比较，迟到结果不覆盖较新任务，不复活已删除角色。
- 服务重启将中断的任务标记失败，保留已生成的台词；下一次整套生成可重试。
- 保存完成后用已有 SSE 通知小窗重新读取缓存。
- 立绘管理提供「反馈台词管理」入口，按部位查看、编辑和保存当前 30 句台词，也可单独重新生成，不重画图片。保存使用版本检查，避免旧窗口覆盖新内容；不提供区域编辑器或道具设置。
- 台词生成固定使用四条 system 消息：system1 为破甲规则与世界观，system2 为世界观强化，system3 为完整角色人格，system4 为触摸任务与完整 JSON 输出示例。整套立绘附带生成与单独生成共用这一入口。
- 立绘管理中的台词状态行按内容高度排列，不参与剩余空间分配，避免立绘列表上方出现大块留白。
- 原实验版本的配置/区域数据不删除；新版触摸逻辑不读取这些用户标记。

触摸全过程只在前端执行，不请求 LLM、不生图、不写聊天、记忆、好感或背包。与服务器失联、角色睡眠、页面隐藏或切角同步过程中暂停触摸。切角色、收到新的聊天展示、失焦、缩放、第二触点、pointercancel 均取消未完成手势。

## 实现入口

- `agent-core/src/services/standingTouchLines.js`：完整提示词、严格解析、后台任务、保存与读取。
- `agent-core/src/services/expressionStandingService.js`：整套立绘请求并行启动台词任务。
- `web-ui/src/utils/standingTouch.js`：全身默认判定和缓存随机台词。
- `web-ui/src/components/standing/StandingInteractionLayer.vue`：原生指针、键盘和 SVG 命中层。
- `web-ui/src/components/standing/StandingInteractionControls.vue`：缓存加载、局部对白和状态隔离。
- `web-ui/src/views/StandingDisplayView.vue`：原有小窗舞台集成，不新增展示体系。

## 触摸形变补充（2026-10-02）

立绘保持同一 DOM 与图片实例，按下时 120ms 内轻微压缩，松手后用 820ms 的六段形变回弹。头顶偏纵向压缩；脸、肩与手偏轻微侧倾；躯干压缩；腿脚轻微缩起。方向取触点左右，使用 PNG 的缩放、错切和旋转，不需要 Live2D、额外图片或模型调用。脚底为形变支点，命中层随图片一起变化。

再次触摸从当前形变接续，不重建图片；取消手势平滑回位，卸载清理动画。系统减少动态效果模式只保留 480ms、最大 1.6% 的轻柔缩放回位，省略位移、旋转与振荡。既有环境呼吸和晃动继续遵从减少动态效果设置。

点击视觉反馈改为触点处两圈错开的圆形波纹，向外扩散并淡出；移除三颗星星和按压区域着色，保留立绘形变。波纹不接收指针事件，随本次反馈结束或组件卸载清理。

肩膀与颈部合并为「肩颈」，共用原肩膀键与三句台词；旧数据读取时兼容，触摸范围覆盖原先两者区域。反馈台词管理入口位于 es-toolbar 右侧。
